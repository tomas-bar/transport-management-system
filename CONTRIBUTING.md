# Development

Use Node.js 24, `npm ci`, then `npm run dev`. Run `npm test`, `npm run build` and `npm run check:documents` before submitting a change. Check desktop and phone layouts when preview infrastructure is available; report unavailable verification honestly.

Keep domain rules independent of React, persistence in adapters, controls in components and screen composition in pages. Use English for code/documentation and natural Lithuanian for visible copy. Preserve keyboard focus, responsive controls, physical stop numbering and the distinction between arrival and handover.

Document current behavior and operational limits. Avoid revision logs and abandoned implementation notes in product documentation. Commit coherent, validated changes with concise English messages.

Keep secrets, runtime databases, backups, dependencies, generated output and deployment identity out of GitHub. Fixtures in `src/data/` must remain included. No project license has been selected; preserve bundled asset notices.
